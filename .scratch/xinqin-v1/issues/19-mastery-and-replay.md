# 19: 掌握度与回放——「刚才那遍是我的」

**What to build:** 一局结束后能被听见、被留下。结算画面按本局数据判三档掌握度（初演 / 弹熟 / 精熟）
并给一张一屏可读的演奏卡（曲名、难度、评级、精度、最长连击、掌握度徽记、是否刷新纪录）；
提供「听我的演奏」——把本局**最后 20 秒**（含终章）重放一遍，玩家弹中的音叠在伴奏上，
漏掉的音不响。回放只在结算这一刻有效，离开即散，不写本地存储、不生成可回访的播放器。
曲库的难度格用三档徽记显示掌握度。掌握度只描述这一局发生过什么，不做任何专业承诺。

**Blocked by:** 18（伴奏声部）——回放的意义是把你的演奏叠在伴奏上重听，所以要等伴奏落地

**Status:** resolved

**Branch:** `ticket/19-mastery-replay`

- [x] 结算显示本局掌握度档位（初演 / 弹熟 / 精熟）；曲库对应难度格显示同档徽记
- [x] 纪录结构扩展为存评级 + 最大连击 + 精度 + 失误数；读到旧版纪录不报错，按缺字段降级为只能判到「弹熟」
- [x] 掌握度判定：胜局 + 任意评级 = 初演；评级 ≥ A = 弹熟；零失误且精度 ≥ 90% = 精熟；败局不入册（沿用现状）
- [x] 结算页有「听我的演奏」：播放本局最后 20 秒（不足 20 秒则从头），玩家命中的音与伴奏同时响
- [x] 回放中漏掉的音不发声（与静置对局同样安静），证明回放的是真实演奏而非补全
- [x] 离开结算画面后回放不可再访问：不写本地存储、不出现任何入口（检查 local storage 无新增键）
- [x] 演奏卡一屏可读，不出现横向滚动；1440×900 与 800×600 下都不裁字
- [x] 纯函数测试覆盖：掌握度边界（0 命中 / 评级 C / A / S / 零失误 + 90% 双条件 / 有失误但精度 ≥ 95%）、
      旧纪录降级、回放裁剪（空演奏、短于 20 秒、跨终章、起点早于第一颗音的负偏移）
- [x] 全量测试与构建绿；不改变任何对局数值与谱面

## Comments

**2026-10-31 · 实现与验证同批**

### 1. 缝在哪

- **缝一（纯核心 · 掌握度）**：`src/core/mastery.ts`——`masteryFor(胜负 / 评级 / 精度 / 失误数)` 判三档，
  败局读出 null（不入册）；`masteryFromRecord(纪录)` 读本机纪录，旧纪录缺精度/失误数时**不猜值**，
  判档自然降级为只能到弹熟（评级 A/S 照算弹熟，S 不会被猜成精熟）；`MASTERY_LABELS` 与 `masteryLine`
  是徽记与结算那一行说明（只说这一局发生过什么，不写「已掌握此曲」这类承诺）。
  唯一门槛常量收在 `config.MASTERY.MASTERED_ACCURACY`（0.90，边界含等号）。
- **缝二（纯核心 · 回放裁剪）**：`src/core/replay.ts`——`replayPlanFor(演奏记录, 伴奏计划, 结束时刻, 终章时刻)`
  给出窗口 `[from, to]`、要发声的命中音（升序、相对起点）、窗口内伴奏、终章相对时刻、命中/漏数。
  闭区间、两端钳在 0 以上：起点之前的音（哪怕早 1 毫秒）不进计划，相对偏移永不为负；
  Miss 不进 `notes`，只记一笔漏数——回放的是真实演奏，不是补全。
- **缝三（存储）**：`records.BestRecord` 增 `accuracy` / `missCount`（可选），`recordResult` 改吃 `RunStats`
  （评级 / 连击 / 精度 / 失误数一并入册）。比较语义不变（评级优先、同级比连击）。
- **装配层**：`main.ts` 在局内把判定事件抄成 `playedNotes`（内存数组，开新局清空）；结算页用
  `replayPlanFor` 排版声音，经现有 lookahead 调度器（ADR-0010）把音排进音频时间线；
  `Piano.play` 新增一个可选的 destination，回放走一条一次性支路（接在 musicBus 上，同一「琴声音量」），
  离开结算时 disconnect + 丢弃未到期调度。画布、音频节点图与听感按仓库口径不做单测。

### 2. 浏览器实测证据（headless Chrome + vite dev，`?auto` 钩子）

- **胜局演奏卡**（`?auto=perfect&song=fur-elise&chart=easy`，整首 2:13 走完，79 颗全 Perfect）：
  卡面读到「致爱丽丝 · 简单 · 新纪录 / S / 精度 100.0% / 最长连击 79 / 掌握度 精熟」，
  脚注「这一局零失误，精度九成以上」，回放脚注「最后 20 秒 · 命中 11 颗 · 漏 0 颗 · 含终章」。
- **纪录结构**：该局后 `xinqin.records.v2` 为
  `{"fur-elise":{"easy":{"rating":"S","maxCombo":79,"accuracy":1,"missCount":0}}}`——精度与失误数确实入册。
- **旧纪录降级**：把同一个键改写成旧格式 `{"fur-elise":{"easy":{"rating":"S","maxCombo":79}}}` 后重进曲库，
  该难度格徽记读「弹熟」（`mastery-seasoned`），不报错、不把 S 猜成精熟。
- **败局**（`?auto=idle&song=fur-elise&chart=easy`，t ≈ 30.0 血尽）：卡面评级 C、掌握度「未入册」、
  脚注「这一局未入册（败局不计掌握度）」，回放脚注「最后 20 秒 · 命中 0 颗 · 漏 12 颗」，
  head 上还印着「本机最佳 S · 连击 79」。命中为零时计划里根本没有旋律音。
- **一屏可读**：1440×900 与 800×600 两档实测，`document.documentElement.scrollWidth === innerWidth`
  （无横向滚动），`.screen` 内所有叶子文本元素矩形都落在视口内（无裁字）；演奏卡 560×208 / 560×179，
  败局卡同样两档无溢出。
- **回放不可回访**：点「听我的演奏」前后 `localStorage` 键集合完全一致（全程只有 `xinqin.records.v2`，
  且它由胜局入册写入，不是回放写的）；`__xq.replayPlaying` 由 false → true，按钮文字转「再听一遍」；
  点「返回曲库」后按钮不复存在、`replayPlaying` 转 false、地址栏无 hash 变化。
- `npm test` 326/326 绿（基线 304 + 新增 22），`npm run build` 绿。

### 3. 没有动的部分

- 判定窗、伤害、血量、咬线、充能、琴心、三首曲目谱面与 `docs/calibration.md` 定标：一个数值都没改
  （`config` 只新增了 `MASTERY` 一个常量块）。
- 票 17 的进度轨与「走到 N%」、票 18 的伴奏与音频主时钟：行为不变。`progress.finaleAtOf` 只是把
  原先写在 `songProgress` 里的终章时刻推导提成导出函数，回放与进度轨共用同一处定义，读数不变。
- 回放不重跑模拟器、不重放怪物动画、不产生任何新存储键，也不出现可回访的入口。
- 已知（**非本票引入**）：800×600 下曲库底部那行提示（「↑↓ 选曲 …」）会被视口裁掉约 28px；
  把新增的掌握度徽记隐藏后裁剪量不变（628 → 628），说明是曲库页面本来就超高一屏，本票未加剧。

### 4. 待真人试听 / 试玩

- 回放的听感：命中音叠在伴奏上是否真的「像刚才那一遍」，20 秒长度够不够、结尾收不收得住。
