# 19: 掌握度与回放——「刚才那遍是我的」

**What to build:** 一局结束后能被听见、被留下。结算画面按本局数据判三档掌握度（初演 / 弹熟 / 精熟）
并给一张一屏可读的演奏卡（曲名、难度、评级、精度、最长连击、掌握度徽记、是否刷新纪录）；
提供「听我的演奏」——把本局**最后 20 秒**（含终章）重放一遍，玩家弹中的音叠在伴奏上，
漏掉的音不响。回放只在结算这一刻有效，离开即散，不写本地存储、不生成可回访的播放器。
曲库的难度格用三档徽记显示掌握度。掌握度只描述这一局发生过什么，不做任何专业承诺。

**Blocked by:** 18（伴奏声部）——回放的意义是把你的演奏叠在伴奏上重听，所以要等伴奏落地

**Status:** resolved

**Branch:** `ticket/19-mastery-replay`

- [x] 结算显示本局掌握度档位（初演 / 弹熟 / 精熟）；曲库对应难度格显示同档徽记
- [x] 纪录结构扩展为存评级 + 最大连击 + 精度 + 失误数；读到旧版纪录不报错，按缺字段降级为只能判到「弹熟」
- [x] 纪录另存一条**单调最佳事实**（零失误局的最高精度，只升不降）：一局「零失误 + 精度 ≥ 90%」
      即使评级/连击不如旧纪录也留下精熟依据，曲库徽记不回退
- [x] 回放播完按音频时钟自行复位（`__xq.replayPlaying` 回 false、按钮回「听我的演奏」）；
      重复点「听我的演奏」先停再放，不叠音
- [x] 掌握度判定：胜局 + 任意评级 = 初演；评级 ≥ A = 弹熟；零失误且精度 ≥ 90% = 精熟；败局不入册（沿用现状）
- [x] 结算页有「听我的演奏」：播放本局最后 20 秒（不足 20 秒则从头），玩家命中的音与伴奏同时响
- [x] 回放中漏掉的音不发声（与静置对局同样安静），证明回放的是真实演奏而非补全
- [x] 离开结算画面后回放不可再访问：不写本地存储、不出现任何入口（检查 local storage 无新增键）
- [x] 演奏卡一屏可读，不出现横向滚动；1440×900 与 800×600 下都不裁字
- [x] 纯函数测试覆盖：掌握度边界（0 命中 / 评级 C / A / S / 零失误 + 90% 双条件 / 有失误但精度 ≥ 95%）、
      旧纪录降级、回放裁剪（空演奏、短于 20 秒、跨终章、起点早于第一颗音的负偏移）
- [x] 全量测试与构建绿；不改变任何对局数值与谱面

## Comments

**2026-10-31 · 实现与验证同批**

### 1. 缝在哪

- **缝一（纯核心 · 掌握度）**：`src/core/mastery.ts`——`masteryFor(胜负 / 评级 / 精度 / 失误数)` 判三档，
  败局读出 null（不入册）；`masteryFromRecord(纪录)` 读本机纪录，旧纪录缺精度/失误数时**不猜值**，
  判档自然降级为只能到弹熟（评级 A/S 照算弹熟，S 不会被猜成精熟）；`MASTERY_LABELS` 与 `masteryLine`
  是徽记与结算那一行说明（只说这一局发生过什么，不写「已掌握此曲」这类承诺）。
  唯一门槛常量收在 `config.MASTERY.MASTERED_ACCURACY`（0.90，边界含等号）。
- **缝二（纯核心 · 回放裁剪）**：`src/core/replay.ts`——`replayPlanFor(演奏记录, 伴奏计划, 结束时刻, 终章时刻)`
  给出窗口 `[from, to]`、要发声的命中音（升序、相对起点）、窗口内伴奏、终章相对时刻、命中/漏数。
  闭区间、两端钳在 0 以上：起点之前的音（哪怕早 1 毫秒）不进计划，相对偏移永不为负；
  Miss 不进 `notes`，只记一笔漏数——回放的是真实演奏，不是补全。
- **缝三（存储）**：`records.BestRecord` 增 `accuracy` / `missCount`（可选），`recordResult` 改吃 `RunStats`
  （评级 / 连击 / 精度 / 失误数一并入册）。比较语义不变（评级优先、同级比连击）。
- **装配层**：`main.ts` 在局内把判定事件抄成 `playedNotes`（内存数组，开新局清空）；结算页用
  `replayPlanFor` 排版声音，经现有 lookahead 调度器（ADR-0010）把音排进音频时间线；
  `Piano.play` 新增一个可选的 destination，回放走一条一次性支路（接在 musicBus 上，同一「琴声音量」），
  离开结算时 disconnect + 丢弃未到期调度。画布、音频节点图与听感按仓库口径不做单测。

### 5. v1.4 两轴审查修复（2026-11-01）：A1 精熟不可达、A2 回放不复位、A4 曲库裁字

两个都是实测能重现的真缺陷，修法与证据如下。A4 一并修（同一轮审查提出）。

**A1 精熟的徽记在曲库里不可达**

- 原状：`recordResult` 只在评级/连击**更优**时才写纪录，于是「零失误 + 精度 97% 但连击低」的一局
  根本不入册；`masteryFromRecord` 只能读那一局 A 级纪录的精度/失误数，徽记永远停在弹熟。
- 修法：纪录增加单调最佳事实 `flawlessAccuracy`（**零失误局**的最高精度，只升不降、与评级/连击无关），
  无论是否刷新评级/连击都更新；`masteryFromRecord` 改用它判精熟。`recordResult` 的返回值拆成
  `improved`（结算页「新纪录」）与 `updated`（纪录变了、必须写回存储）两个量——只推了事实的那一局
  也要落盘，否则刷新页面就丢。旧纪录没有这个字段时**不猜**，仍降级为弹熟。
- 为什么不拆 `bestAccuracy` + `hasFlawless` 两个独立最大值：那样会把「一局零失误但精度 85%」与
  「一局精度 97% 但有失误」拼成一个**从未发生过**的精熟。一条「零失误局的最高精度」既单调、
  又只描述真实发生过的同一局。
- 浏览器实测（800×600，直接写 `xinqin.records.v2` 后重进曲库读徽记）：
  - `{rating:'A', maxCombo:42, accuracy:0.88, missCount:0, flawlessAccuracy:0.97}` → 「A 连击 42 **精熟**」
    （旧代码会判弹熟：accuracy 0.88 < 0.90）；
  - 旧格式 `{rating:'S', maxCombo:79}` → 「S 连击 79 **弹熟**」，不报错、不冒充精熟；
  - `{rating:'A', …, flawlessAccuracy:0.85}` → 「A 连击 61 **弹熟**」。
  - 一局真实胜局（`?auto=perfect&song=fur-elise&chart=easy`）后存储为
    `{"fur-elise":{"easy":{"rating":"S","maxCombo":79,"accuracy":1,"missCount":0,"flawlessAccuracy":1}}}`。
  - 单测钉住「不回退」：先 A 零失误 97%，再构造一局 S 但精度 50%、5 次失误、连击 40 →
    `flawlessAccuracy` 仍是 0.97，`masteryFromRecord` 仍读精熟。

**A2 回放状态不复位**

- 原状：`__xq.replayPlaying` 是一个只置 `true` 的布尔量，20 秒放完也没人复位，按钮永远停在
  「再听一遍」（实测重现）。修法：壳层只存一份播放状态（`replayPlaybackAt(now, plan)` = 起点 + 时长），
  逐帧用纯函数 `replayActiveAt(playback, now)` 判「还在播吗」，结论同时写按钮文案与 `__xq` 读数；
  `startReplay` 一律先 `stopReplay`（丢弃未到期调度 + `disconnect` 旧支路）再排新的。
- 浏览器实测（同一局结算页，800×600；按钮与读数与分辨率无关）：
  - 点「听我的演奏」→ `replayPlaying = true`、按钮「再听一遍」、`replayNotes = 11 / misses = 0`；
  - 窗口内再点一次 → 仍是 true（换新一遍），`createGain` 计数 +1、`disconnect` 计数 +1
    （旧支路确实被断开，先停再放）；
  - 等过 21.5 秒（窗口 20 秒 + 0.12 余量）→ `replayPlaying = false`、按钮回「听我的演奏」。
  - 纯函数测试还钉住：终点不含（`startAt + 20` 即 false）、短局按实际窗口结束、两份播放状态互不牵连。

**A4 800×600 曲库裁字（`index.html`）**

- 原状：`.screen` 内容 628px、视口 600px，底部提示行被裁 28px 且不可滚。修法：加
  `@media (max-height: 660px)` 收紧非结算画面的字号/间距/琴键高度，并把 `.screen` 做成可内部滚动的
  兜底（方向键被游戏吃掉，只能靠滚轮）。
- 实测（800×600，含掌握度徽记的曲库）：`.screen` 高 564px、底部提示行 541–568 全部落在视口内，
  所有叶子文本元素**零溢出**、无横向滚动；1440×900 内容 652px 照旧（媒体查询不生效）；
  800×520 时面板内部可滚（scrollHeight 564 > clientHeight 520），不再裁掉不可达的字。
- 结算页两档仍无裁字（800×600 内容 359px，最小 top 128 / 最大 bottom 472）。

`npm test` 348/348 绿（本轮新增 22 项），`npm run build` 绿；对局数值与谱面零改动。
