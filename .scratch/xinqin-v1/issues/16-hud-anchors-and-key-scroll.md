# 16: 状态读数回到视线里（菜单方向键不再滚屏、气血条落底、琴心进度上两侧）

**What to build:** 用户试玩后的三条反馈：「在菜单的地方按上下左右方向键会导致屏幕也跟着移动」「现在特殊技能的进度消失了，就是多少次触发一次特殊技能的进度看不到了」「我的血条在哪，好像也看不到，最好放在下面吧」。第一条是按键归属：菜单消费方向键，却从不 `preventDefault`，键位的浏览器默认行为（滚动文档、空格翻页）原样留给宿主。后两条是 HUD 锚位：气血条挂在屏幕最顶边（8px 通栏）、琴心蓄能槽收在左上角（240×9、只靠颜色深浅表达进度），而玩家的视线全程在下落区与判定线上——状态画在视区外，等于没画。本票一次性处理三件事：吞掉游戏按键的浏览器默认行为、气血条搬到屏幕下缘并给整数读数、琴心蓄能改成左右两条竖直槽并在槽顶印「琴心 已蓄/30」。

## Comments

**2026-10-31 · 开票与改动同批**

### 1. 菜单里方向键为什么会把画面带走

`onKeyDown` 的老写法是「这一屏处理了键就 `return`」，全篇没有一次 `preventDefault`：方向键与空格于是同时被游戏和浏览器消费，浏览器那半份默认行为就是滚动画布所在的文档。本地无头 Chrome 在 1280×600 与 900×300 下都量不到文档滚动（`document.scrollingElement.scrollTop` 恒 0、`documentElement.scrollHeight === innerHeight`），说明 `html,body{overflow:hidden}` 在 Chromium 里已经挡住了这条路径——即这一条依赖宿主（iframe 嵌入、矮窗口、把 overflow 当纯视觉裁剪的实现都会漏）。修法不依赖宿主：游戏自己消费的键一律 `preventDefault`，焦点在表单控件上时放行。

### 2. 浏览器实测证据

- **曲库**：↑ ↓ ← → 与空格的 keydown 全部 `defaultPrevented = true`；文档与 `#overlay` 的 `scrollTop` 全程 0。
- **设置**：焦点在「音画偏移」滑条上时 `defaultPrevented = false`，→ 键把偏移从 `0 毫秒` 推到 `+5 毫秒`（原生微调没被抢走）。
- **HUD 满负荷**（`?auto=perfect&song=canon-in-d&chart=easy`，1440×900）：左右竖槽读「琴心 25/30」，槽内 83% 填充；底部气血条显示「气血」「100 / 100」。
- **掉血**（`?auto=idle&song=canon-in-d&chart=medium`，1440×900）：hp 100→90→…→30 逐口同步缩短，读数跟着走；降到 30% 时朱砂描边呼吸、标签转朱砂。
- **窄窗**（800×600）：竖槽与「琴心 x/30」不压键位列与下落音符，气血条与键位标签留出余量，无裁字。
- **曲库重排**：修前键位图示随难度在 322px（简单/中等）与 552px（高级）之间跳，居中后的左边缘从 479px 滑到 364px；加定宽框后 `.piano-frame` 恒为 560px、开战按钮左边缘恒为 430px，换难度只剩键数变化。
- `npm test` 232/232 绿，`npm run build` 绿。

### 3. 没有动的部分

- 一个对局数值都没动：血量、咬线伤害、充能速率、判定窗口、剑气伤害、琴心倍率全部原值。
- 连击数与倒计时仍在上方——本票只搬「状态读数」，没有重排打击反馈。
