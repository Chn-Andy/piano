# 17: 进度轨——一首多长、我走到哪

**What to build:** 演奏全程能看出「还有多久」。屏幕顶部一条细时间轨：左端已过时间、右端总长（m:ss），
终章位置以朱砂点预告、到达即点亮；每次余韵后浮出「第 N / M 句」并在约两秒后淡出，最后一个乐句开始时
浮出「最后一句」。败局结算给出「走到 xx%，血尽」，胜局是 100%。曲库的难度格显示该谱面时长。
不引入大字倒计时（开演前那四拍倒计时原样保留）。这条轨是 HUD 锚位的唯一例外：其余状态读数仍在下半区
（ADR-0014），进度轨回屏幕最顶边——它是慢变量，不与判定抢注意力。

**Blocked by:** None（可立即开始）

**Status:** resolved

- [x] 战斗中屏幕顶部有一条细进度轨（厚 ≤ 4px、左右各留边距、与顶边留白），左端读已过、右端读总长，均为 `m:ss`
- [x] 终章时刻在轨上以朱砂点预告；跨过终章后该点变为点亮态
- [x] 每次余韵触发后 0.3 秒内浮出「第 N / M 句」，约 2 秒后淡出，同一时刻只显示一条
- [x] 最后一个乐句开始时浮出「最后一句」，与句序号一闪可辨（不叠字）
- [x] 暂停/恢复后读数连续（时钟冻结，不跳变）；倒计时阶段轨为空白态，不出现乱数
- [x] 败局结算显示「走到 N%」（按当时的谱面时刻与总长算，四舍五入到整数）；胜局显示 100%
- [x] 两种败局的措辞分开、各有理由：血尽读「走到 N%，血尽」且**封顶 99%**（99.6% 四舍五入就是 100%，
      但「血尽」绝不能读成已经走完——差一口气也是差）；歌毕仍有墨妖读「走到 N%，墨妖未绝」
      （血没空，是另一种输法，不能也叫「血尽」）
- [x] 曲库每个难度格显示该谱面时长（`m:ss`），与谱面总长一致
- [x] 1440×900 与 800×600 下实测：进度轨、两侧蓄能槽、底部气血条、键位标签互不重叠，也不遮挡下落音符与判定线
- [x] 纯函数测试覆盖：`t` 为负（倒计时）、0、中段、恰好末尾、超出末尾、无乐句谱面（句序号回退为不显示）
- [x] 全量测试与构建绿；不改变任何对局数值（血量、咬线、充能、判定窗口、伤害、谱面）

### 4. v1.4 两轴审查：两种败局口径的补记（2026-11-01）

审查指出票面 AC 只覆盖了「血尽」一种败局，而 `progressLine` 实际有第三种读数
（歌毕仍有墨妖）与一处 99% 封顶。**代码不改**（这是 17 号票当时的有意设计，理由写在
`src/core/progress.ts` 的注释里），把口径补进 AC，并在此记录证据：

| 局面 | 结算读数 | 依据 |
|---|---|---|
| 胜局（`cleared`） | 「走到 100%」 | 胜利定义就是撑到歌末；不论当时时钟走到哪都读 100% |
| 血尽（`player-hp-empty`） | 「走到 N%，血尽」，N 封顶 99% | 99.6% 四舍五入就是 100%，但「血尽」不能读成走完；`Math.min(99, percent)` |
| 歌毕仍有墨妖（`monsters-remain`） | 「走到 N%，墨妖未绝」 | 血没空，只是没清完场——措辞必须与「血尽」分开，否则玩家以为自己是被打死的 |

**实测（本轮重跑，headless Chrome + vite dev，800×600）**：

- 血尽：`?auto=idle&song=fur-elise&chart=easy`，`__xq.phase` 在 `t = 30.0` 转 `ended`，
  结算首行读到「走到 23%，血尽」（30.0 / 133.3 = 0.225；此前 17 号票在卡农上读到
  「走到 17%，血尽」是 30 / 175，同一口径、不同曲长）。
- 墨妖未绝：这条读数由**纯函数测试**钉住（`progress.test.ts`：「歌毕仍有墨妖 →
  `走到 100%，墨妖未绝`」），reason 由模拟器 `OutcomeEvent.reason = 'monsters-remain'`
  直接传给 `progressLine`（`main.ts` 只做接线）。浏览器里没有稳定的「歌毕留怪」钩子
  （`?auto=idle` 必先血尽、`?auto=perfect` 必清场），故未做端到端重放——口径本身有单测。
- 99% 封顶同样由单测钉住（`t = 31.9` → 「走到 99%，血尽」；`t = 40` 超出曲长仍 99%）。
- `npm test` 349/349 绿、`npm run build` 绿（本轮全量）。
