# 17: 进度轨——一首多长、我走到哪

**What to build:** 演奏全程能看出「还有多久」。屏幕顶部一条细时间轨：左端已过时间、右端总长（m:ss），
终章位置以朱砂点预告、到达即点亮；每次余韵后浮出「第 N / M 句」并在约两秒后淡出，最后一个乐句开始时
浮出「最后一句」。败局结算给出「走到 xx%，血尽」，胜局是 100%。曲库的难度格显示该谱面时长。
不引入大字倒计时（开演前那四拍倒计时原样保留）。这条轨是 HUD 锚位的唯一例外：其余状态读数仍在下半区
（ADR-0014），进度轨回屏幕最顶边——它是慢变量，不与判定抢注意力。

**Blocked by:** None（可立即开始）

**Status:** resolved

### 1. 缝在哪

- **缝一（纯核心）**：新增 `src/core/progress.ts`——`songProgress(谱面, t)` 给出已过/总长/比例/
  句序号/句总数/终章时刻/末句起点；`formatClock` 是轨两端与曲库格子的同一口径；
  `progressLine` 是结算那句「走到 N%」；`progressCueAt` 是句提示的时间轴（余韵后 2 秒、末句压过句序号）。
  时间只从谱面时间轴来（ADR-0010 的音频主时钟域），不进模拟器状态、不参与判定。
- **缝二（纯几何）**：新增 `src/render/hudGeometry.ts`——进度轨、两侧蓄能槽、气血条、键位标签的
  矩形与键区宽度都收敛在这里，渲染层照此绘制。画布像素断言不了，「谁占哪块矩形」可以：
  `hudGeometry.test.ts` 在 1440×900 与 800×600（7 白键与最挤的 12 白键各一遍）钉住两两不相交。
- 装配层（`main.ts`）与渲染层（`renderer.ts`）只做接线，不测画法（与既有口径一致）。

### 2. 浏览器实测证据（headless Chrome，本地 dev server）

- **曲库**：九格难度全部印时长——卡农 2:55 / 致爱丽丝 2:13 / 春江花月夜 3:38，与谱面 `duration` 一致。
- **倒计时**：`t = −1.96` 时，轨带（y 10–13）、读数带（14–31）、提示带（31–42）三带的像素全部是纸色
  （min 亮度 209–210、无一个 < 180 的像素）；开演后 `t = 0.58` 同一带出现墨轨与「0:00 … 2:55」。
- **句提示**（`?auto=perfect&song=canon-in-d&chart=easy`）：`__xq.progressCue` 依次读到
  「第 2 / 17 句」「第 5 / 17 句」…「第 16 / 17 句」；`t = 167.3` 起读到「最后一句」（末句起点 167），
  且 167.0 时还是「第 16 / 17 句」——同一时刻只有一条，末句压过句序号。
- **终章点**：同一点（x≈1402）在末句之前是空心环（像素 185,128,114，朱砂 55% 压在纸上），
  `t = 173` 之后变成实心朱砂（160,61,44）——预告 → 点亮。
- **暂停/恢复**：Esc 暂停 1.5 秒，`__xq.t` 两次读数完全相等（9.721 / 9.721）；恢复后从 9.721 继续到 10.592。
  读数只取主时钟，没有第二个时钟可跳。
- **败局结算**（`?auto=idle`，800×600）：血尽于 `t ≈ 29.9`（比例 0.172），结算显示「走到 17%，血尽」。
- **胜局结算**：跑到歌末（比例 1.0）显示「走到 100%」。175 秒的曲子在本机浏览器会话里撑不到底
  （连接约两分钟被断），这一轮把音频主时钟读数临时乘 3 快进（只在页面里打补丁，未入库）——
  判定用的是调度时刻而非帧时刻，82 颗音符仍全 Perfect、零失误，胜负与读数不受影响。
- `npm test` 282/282 绿（基线 232 + 新增 50），`npm run build` 绿。
- **待真人试玩**：轨的粗细/字重、朱砂点大小、句提示的淡出手感与「最后一句」在余光里够不够扎眼，
  这些是视觉判断，上述像素只证明「有画、在带内、互不重叠」。
