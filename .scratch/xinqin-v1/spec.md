# SPEC-0001 ·《心琴》v1

Label: `ready-for-agent`
状态: 已确认（2026-10-24 设计访谈收口；v1.5 双语增补于 2026-11-01 确认）
治理文档: GLOSSARY.md、docs/adr/0001–0017

## Problem Statement（问题陈述）

键盘节奏游戏同质化严重：Piano Tiles / Magic Tiles 一类产品清一色霓虹风、纯分数反馈，玩家弹对了只有数字变大，没有任何情绪回报，也没有"用键盘弹钢琴"的真实手感。玩家想要一个：真有钢琴手感的键盘弹奏体验、有画面感的战斗目标、以及能"欣赏自己弹奏成果"的时刻。

## Solution（解决方案）

《心琴》（名暂定）：水墨武侠风的桌面键盘节奏战斗游戏。每首歌是一场斗琴——音符随歌下落，玩家按真实钢琴布局的字母键弹奏，命中化作剑气攻击墨妖；连击提升伤害倍率，和弦是重击，miss 会挨打掉血；乐句末自动触发「余韵」演出引爆本句战果，歌曲高潮以「终章」击败墨主。v1 含三首公版曲目 × 三难度，浏览器打开即玩，零后端。

## User Stories（用户故事）

1. 作为新玩家，我想首次进入时得到约 30 秒的键位引导，以便不用查文档就知道哪个字母键对应哪个音。
2. 作为新玩家，我想在引导中试按白键立即听到琴声，以便建立"按键—声音"的直觉。
3. 作为新玩家，我想从简单难度（仅 7 个白键）开始，以便不被黑键布局劝退。
4. 作为玩家，我想看到曲库列表（卡农 / 致爱丽丝 / 春江花月夜）及各难度与本机最佳纪录，以便选择这一局斗琴。
5. 作为玩家，我想在开战前看到本难度的键位图示，以便把手放对位置。
6. 作为玩家，我想随时暂停、继续或放弃返回曲库，以便处理现实中的打断。
7. 作为玩家，我想音符落到判定线时按键，获得 Perfect / Good / Miss 三级判定，以便知道自己的精度。
8. 作为玩家，我想命中时立即听到琴声并看到剑气飞出，以便获得弹奏的即时爽感。
9. 作为玩家，我想连击持续累积并直观看到伤害倍率在涨，以便感到越弹越强。
10. 作为玩家，我想弹中和弦音符（同时落下的多键）触发重击，以便体验物理键盘独有的双手技巧。
11. 作为玩家，我想 miss 时明确看到墨妖反击、自己掉血，以便理解失败的因果。
12. 作为玩家，我想血空时立即看到失败画面并可一键整首重开，以便不受挫败地再来一次。
13. 作为玩家，我想撑到歌末清完怪（含墨主）时看到胜利画面，以便获得完整的完成感。
14. 作为玩家，我想每个乐句结束时余韵自动引爆本句剑气，以便欣赏自己刚弹完的这一句。
15. 作为玩家，我想弹得好的乐句余韵更壮观，以便"看杰作"成为弹好的奖励。
16. 作为玩家，我想歌曲高潮处出现终章大演出击败墨主，以便获得电影式的高潮记忆点。
17. 作为玩家，我想墨妖的血条、受击、死亡在不转移视线的情况下凭余光可感知，以便边弹边掌握战况。
18. 作为进阶玩家，我想中等难度加入黑键（12 键布局），以便逼近真钢琴的手感。
19. 作为高手玩家，我想高级难度扩键域并出现更多和弦，以便有可持续的挑战。
20. 作为玩家，我想结算画面显示评级（S/A/B/C）、最大连击与伤害统计，以便衡量本场表现。
21. 作为玩家，我想我的最佳纪录保存在本机，以便下次打开时超越自己。
22. 作为玩家，我想设置里有音画偏移校准滑条，以便在我这台设备上判定公平。
23. 作为玩家，我想分别调节音乐与战斗音效音量，以便获得舒适的听感。
24. 作为音游玩家，我想长按不触发重复判定（keydown 去重），以便判定不被键盘重复事件污染。
25. 作为玩家，我想切出浏览器标签页时对局自动暂停，以免回来时血已流空。
26. 作为玩家，我想界面用我读得懂的语言，以便无障碍游玩。（v1.5 起中英双语，见文末增补）
27. 作为玩家，我想游戏是纯网页、打开链接即玩免安装，以便碎片时间随时来一局。

## Implementation Decisions（实现决策）

- **分层**：核心是一个纯数据模拟器（无 DOM / 无音频依赖）：输入 = 谱面 + 以音频时钟计时的按键事件序列，输出 = 判定流、连击状态、玩家与怪物血量演变、余韵/终章触发点、结算评级。渲染（Canvas 2D）与音频（Web Audio）作为薄壳消费模拟器的输出事件流。战斗数值不是"分数换皮"散落各处，而是全部收进模拟器。
- **谱面格式**：项目唯一的核心数据契约（JSON）。包含：音符（时刻、键位、和弦分组）、乐句边界、余韵窗口（窗口内保证无音符）、难度元数据（键位范围、量化网格）。它既是 MIDI→谱面转换器的输出，也是模拟器与渲染器的输入。
- **MIDI→谱面转换器**：构建期工具。公版 MIDI → 三难度谱面。难度规则：键位映射范围（简单 7 白键 / 中等 12 键 / 高级扩域）、量化网格粗细、密度过滤、和弦识别、基于休止检测的乐句切分。判定窗口、密度阈值等全部是集中的可调常量，初值定标在实现阶段完成。
- **键位映射**：白键 `A S D F G H J`，黑键 `W E T Y U`（嵌于白键之间，同真钢琴八度），高级难度向两侧扩域。`Esc` 暂停。v1 布局固定，不做重映射。
- **判定与数值**：三级判定，仅 Miss 断连击并触发墨妖反击；初始窗口 Perfect ±50ms / Good ±120ms（常量，可调）。伤害、倍率曲线、双方血量为配置常量。
- **余韵**：乐句末自动触发，依据谱面编码的乐句边界；规模 = 乐句表现分（连击 + 判定质量）分档；演出期间音符暂停由"余韵窗口内无音符"这一谱面不变式保证。
- **音频主时钟**：游戏时间轴以 `audioContext.currentTime` 为准，不跟随 rAF 时间戳（ADR-0010 于实现首张票内补立）。钢琴 = CC 授权采样包按需加载；战斗音效 = 程序合成；音频调度采用 lookahead 机制。
- **持久化**：localStorage——各歌各难度最佳评级与最大连击、设置（音量、音画偏移）。
- **UI**：中文（v1.5 起中英双语，见文末增补与 ADR-0017），单页应用无刷新，三个画面：曲库 → 斗琴 → 结算。

## Testing Decisions（测试决策）

- **什么是好测试**：只测外部可观察行为（给定谱面与输入 → 可断言的结果），不测内部实现细节；常量定标变化不应破坏测试结构。
- **Seam 1（最高缝）——核心模拟器**：注入固定时钟，喂合成按键事件流（精确时间戳、故意 Miss、和弦齐按/只按一半、长按去重、余韵窗口内的空窗），断言：判定序列、连击中断与恢复、双方血量演变、余韵触发与规模分档、终章、胜负面条件、评级映射。纯逻辑全在此层，这是本项目测试的主战场。
- **Seam 2——MIDI→谱面转换器**：输入 MIDI fixture，断言谱面结构性质：三难度键位范围正确、余韵窗口内无音符（不变式）、难度间密度单调、乐句边界存在、和弦分组合法。
- **不做单元测试的部分**：Canvas 渲染与 Web Audio 回放，靠人工试玩验收。理由：逻辑全部上移进纯模拟器后，画布层只剩绘制。
- 绿地项目无先例，以上两组测试即仓库的测试范式。
- （缝的方案已向用户说明；如对缝的取舍有异议请提出，影响的是两张测试票的范围。）

## v1.1 增补（2026-10-27，用户试玩反馈后的战斗重构）

设计裁定见 ADR-0011、ADR-0012 与 ADR-0004/0007 的增补：

- **怪物推进**：墨妖成群自战场深处向琴阵推进（横向散布、确定性生成、难度决定生成节奏）；抵达琴阵后每 2 拍攻击一次直至被杀。miss 不再直接扣血（ADR-0011）。
- **剑气 AoE**：命中为全屏纵深衰减攻击（前排承伤最多、后排递减），无指向决策（ADR-0012）。
- **异色音符**：寒音（全场击退+减速）/ 毒音（最前怪 DoT）/ 爆音（最前两只重击），转换器确定性编排入谱面，频率约 5–8%。
- **琴心**：连击蓄能，充满自动释放全场爆发「琴心通明」，可在乐句中途触发（ADR-0007 增补）。
- **余韵/终章升格为真实 AoE 伤害事件**：规模随乐句表现分；终章（grand）须能斩首墨主。
- 胜负条件不变：撑到歌末且清空全场（含墨主）为胜。

## v1.4 增补（2026-10-31，演奏幻想：进度、伴奏、掌握度与回放）

设计裁定见 [ADR-0015](../../docs/adr/0015-演奏幻想为主叙事.md)（演奏幻想是主叙事、保真档不做）与
[ADR-0016](../../docs/adr/0016-伴奏只承担和声.md)（伴奏只承担和声，旋律永远归玩家）；
完整访谈记录（事实、四轮问题与决定）见 [grill-performance-fantasy.md](grill-performance-fantasy.md)。

### Problem Statement（问题陈述）

玩家弹完一整首也说不清三件事：「这首多长、我走到哪」「除了我按下的音还有别的音乐吗」
「刚才那一遍好听吗」。当前 HUD 只有倒计时与判定闪示；全程只有玩家自己按下的几个音在响，
miss 处彻底静音（音乐真的会断）；结算只报战斗数字（评级、连击、伤害），没有回放、没有可留下的凭证。
于是「撑到歌末」只是一个数值结局，不构成「我弹下了一首世界名曲」的记忆。

### Solution（解决方案）

三段交付，合起来才叫**演奏幻想**：

1. **进度轨**：屏幕顶部一条细时间轨——已过与总长、终章位置的朱砂点预告、余韵时的句序号、
   末句提示；败局给「走到 xx%」。它回答「还有多久」。
2. **伴奏声部**：由源曲派生的和声骨架（左手/低音），全程自动演奏，让曲子始终成立；
   主旋律永远归玩家，漏音不代弹。它回答「这是那首曲子，不是我一个人的断片」。
3. **掌握度与回放**：三档掌握度入本机纪录并显示在曲库；结算页可以「听我的演奏」——
   本局最后 20 秒（含终章），玩家弹中的音叠在伴奏上重放一遍。它回答「刚才那遍是我的」。

### User Stories（用户故事）

1. 作为玩家，我想在演奏任意时刻知道已过多久与整首多长，以便决定这一口气要不要撑下去。
2. 作为玩家，我想看到终章在进度轨上的位置，以便给最后一段留出力气。
3. 作为玩家，我想在每次余韵后看到「第 N / M 句」，以便把「一句一句」的感觉对上音乐的段落。
4. 作为玩家，我想在最后一句开始时被告知「最后一句」，以便知道收尾要来了。
5. 作为玩家，我想在败局时看到「走到 62%，血尽」，以便知道自己是倒在半途而不是从头就没戏。
6. 作为玩家，我想在曲库看到每首曲子有多长，以便按碎片时间选曲。
7. 作为玩家，我想在弹奏时始终有一层和声在下面托着，以便曲子不至于听着像一个人摸黑找琴键。
8. 作为玩家，我想漏掉一颗音时只丢那一颗、音乐本身不断，以便错误是「缺口」而不是「崩盘」。
9. 作为玩家，我想简单难度的伴奏留白更多，以便听清自己弹的旋律。
10. 作为玩家，我想伴奏永远不替我弹主旋律，以便我的命中与漏音都还听得出来。
11. 作为玩家，我想在一局结束后听到刚才那遍的最后 20 秒，以便真的「听见我弹的这首曲子」。
12. 作为玩家，我想结算有一张能一眼看完的演奏卡（曲名/难度/评级/精度/最长连击/掌握度），以便截图留下这一局。
13. 作为玩家，我想曲库用三档徽记显示每首曲子的掌握度，以便知道哪首已经「拿下」、哪首还差一口气。
14. 作为玩家，我想掌握度只描述这一局发生过什么，而不承诺我的钢琴水平，以便它不被误读成教学质量。
15. 作为音游玩家，我想回放只出现在结算那一刻、不生成可回访的播放器，以便这个游戏不长成一个播放器。
16. 作为玩家，我想伴奏受「琴声音量」控制且不会盖过我的旋律，以便听感自己做主。

### Implementation Decisions（实现决策）

- **进度是纯读数**：由谱面与当前时刻派生（已过/总长/比例/句序号/句总数/终章时刻），
  不进模拟器状态、不参与判定与战斗，任何数值都不因此改变。
- **进度轨的位置是 HUD 锚位的唯一例外**：其余状态读锚在下半区（ADR-0014），进度轨回屏幕最顶边——
  它是慢变量，不与判定抢注意力，也不与两侧蓄能槽、底部气血条争位置。
- **谱面契约新增伴奏声部**：一组（时刻, 音高）事件，由转换器从源曲的非主旋律材料确定性生成；
  它不进判定、不参与战斗、不影响任何定标常量。旧谱面（没有伴奏声部）必须继续可用。
- **伴奏的密度按难度分档**（简单：低音 + 根音；中等：三和弦分解；高级：补内声部），
  **不做**随表现动态加厚——那会把伴奏变成隐藏评分，并与「旋律归玩家」的原则冲突。
- **伴奏走既有音频主时钟**：用与倒计时/墨主登场相同的 lookahead 调度器提前排进音乐轨，
  与玩家琴声共用「琴声音量」；不新增常驻音轨、不引入任何录音素材。
- **卡农例外**：它的源 MIDI 只有单轨、没有可拆的伴奏材料，v1.4 用引擎合成的低频铺底兜底，
  不替换 fixture（替换会改变卡农谱面密度，连带重新定标）。
- **掌握度是纯判定**：由本局结算数据（评级、精度、失误数）判三档——初演（活着弹完全曲）、
  弹熟（评级 ≥ A）、精熟（零失误且精度 ≥ 90%）。纪录结构需扩展以存精度与失误数；
  读到旧版纪录时不报错，降级为只能判到「弹熟」。文案只描述这一局，不做专业承诺。
- **回放只在内存里**：壳层在局内记录每颗音的判定与时刻，结算页据此重放最后 20 秒；
  离开结算画面即释放，不写本地存储、不产生可回访入口。
- **回放不重演战斗**：只播声音 + 静态演奏卡，不重跑模拟器、不重放怪物动画。

### Testing Decisions（测试决策）

- **什么算好测试**：只测外部可观察行为——给定谱面与时刻（或给定结算数据）→ 可断言的读数；
  不测画布与音频节点图；定标常量变化不应破坏测试结构。
- **缝一（沿用最高缝，纯核心）**：进度读数、掌握度判定、回放时间线裁剪三件都由纯函数承担，
  逐分支覆盖：`t` 为负（倒计时）／0／中段／末尾／超出末尾；句序号边界与末句；
  掌握度的 A/C 边界、零失误 + 90% 的双条件；回放窗口的起点、空演奏、跨越终章。
- **缝二（沿用转换器缝）**：伴奏声部的结构性质——同一时刻同音高不得同时出现在旋律与伴奏
  （不代弹）、密度随难度单调、时刻落在曲内、同一 fixture 重复生成结果一致；旧谱面无伴奏仍可加载。
- **持久化**：纪录结构升级的读旧数据路径必须有测试（旧键读入不抛错、可判档位正确降级）。
- **不做自动化测试的部分**：进度轨的视觉、伴奏的听感与音量平衡、回放的听感——靠真实试玩验收
  （与既有画布/音频口径一致）。

### Out of Scope（范围外）

原曲保真档（明确不做，连设计票也不留）、教学/课程/指法提示/进步曲线（ADR-0008 附注）、
真实录音伴奏（BGM 音频素材）、PNG 导出与分享链路、跨局回放与播放器、账号/云存档/排行榜、
换卡农 fixture、按表现动态加厚伴奏。

## v1.5 增补（2026-11-01，双语 UI：中文 / English）

### Problem Statement（问题陈述）

游戏已经上架 itch（v1.4），但整扇门都是中文：商店页、五张截图、封面、README，以及游戏本体里的每一处文字。英文玩家点进来，只能靠曲名和键位猜这是个什么游戏——他们读不懂标题屏那句「水墨斗琴 · 音符落处，剑气斩妖」，也认不出结算卡上的「斗琴告捷」。多数人在看到全中文的第一屏就离开了。与此同时中文侧的一切都已经成立：中文玩家、中文商店页、已有的五张截图与封面，不能为了英文而让位、被替换。

### Solution（解决方案）

界面双语：中文与英文各一套完整文案，默认跟随浏览器语言（`zh` 开头判中文，其余英文），玩家可在设置面板与曲库角标处随时切换，选择被记住。**英文模式下全英文——一个汉字都不留**：标题字、朱砂印、倒计时数词一并英文化，游戏名沿用拼音 *XinQin*。全部玩家可见文案收进一张表（漏一条构建即失败），术语以 `GLOSSARY.md` 的英文名为准。发行物同步双语：itch 商店页一页两段（中文在前、英文在后）、截图 10 张（中文 5 + 英文 5）、新做一张中英并列封面、README 中英两份互链。中文内容一律保留，英文是新增。

### User Stories（用户故事）

4. 作为玩家，我想在设置面板里随时切换语言，以便按自己的习惯读界面。
5. 作为玩家，我想曲库标题旁就有「中 / EN」角标，以便不必进设置就能切。
6. 作为玩家，我想语言选择在下次打开时仍然生效，以便不用每次重选。
7. 作为玩家，我想切语言只改文字、不动音量与音画偏移，以便不必重调设置。

### Implementation Decisions（实现决策）

- **文案表（新建模块，纯层）**：一个 `MsgKey` 联合类型 + 两份 `Record<MsgKey, string>`（中文、英文），漏一条键即 `tsc` 报错；带插值的句子（判定偏差、进度行、掌握度释义、结算统计行、回放读数）是函数，不是调用点拼的模板字符串。模块导出「按语言取一整套文案」的入口，DOM 壳与画布渲染都从它取字。**不引 i18n 库**：两个语言、约 105 条文案，依赖比表本身更贵，且会把键集从类型检查里藏起来。
- **语言解析**：纯函数，输入「浏览器语言 + 已存偏好」，输出 `'zh' | 'en'`；已存偏好为 `null` 表示跟随系统（`zh` 开头含 `zh-CN` / `zh-TW` 判中文，其余与空值、未知值一律英文）。
- **设置**：`Settings` 增加 `locale`（`'zh' | 'en' | null`），**沿用现有 `xinqin.settings.v1` 键、不升版本号**——升版会静默清掉玩家已有的音量与音画偏移。读取时非法值归 `null`。
- **切换入口与生效**：设置面板一行（两个语言按钮）+ 曲库标题右侧常驻「中 / EN」角标；切换后立即重渲染当前画面，并同步文档根元素的 `lang` 与页面标题。**不做全局快捷键**：字母区几乎全被琴键手位占用（白键 A S D F J K L、黑键 W E T Y U，高级难度再占 I O P 与 Z X C）。
- **曲库数据**：曲目条目由「一个标题 + 一句介绍」改为双语，另带一个曲库行专用短名——曲名栏宽约容 12–14 个拉丁字符，*Spring River* 用于曲库，*Moonlight on the Spring River* 用于结算卡与键位引导。曲目 id 与纪录键不随语言改变；难度名、掌握度档位名、异色词缀名同样走文案表。
- **画布渲染**：渲染器接收一整套文案；字体栈按语言切换（英文模式在栈首前置拉丁衬线，**仍不打包字体**）；终章朱印的宽度改为「测量出的字宽 + 两侧朱砂边」，高度与位置不变——**印面围住词，而不是词挤进按两字定死的印面**；和弦重击标记的字号按测量收敛到怪物半径的 1.4 倍以内；倒计时数词随语言（中文仍四三二一，英文 4 3 2 1）。
- **纯层句子**：偏移建议（`rating`）、进度行（`progress`）、掌握度释义（`mastery`）改为接收文案函数后返回句子；这三个模块不再持有任何玩家可见字面量。
- **发行物**：README 拆中文与英文两份并互相链接；itch 描述改为中英两段（中文在前）；截图新增英文 5 张、中文 5 张原样保留；封面新做一张中英并列版，三张原有封面不动；发布粘贴单增一节「双语发布怎么填」。
- **不做**：i18n 库、语言包按需加载、字体打包、浏览器端逐屏 e2e 巡检。

### Testing Decisions（测试决策）

- **什么算好测试**：只测外部可观察行为——给定语言与输入 → 可断言的输出；不测画布像素，不测 DOM 模板结构。文案改动不应破坏战斗与判定测试。
- **Seam A（新增，最高缝）——文案表**：断言两套字典键集完全相同、无空串；**机器守卫**：英文值里出现任何汉字即失败，中文值里出现整句英文即失败（白名单：`XinQin`、评级 `S`–`C`、`×`）；插值函数在给定参数下的输出形状；语言解析的分支（`zh-CN` / `zh-TW` / `en-US` / 空串 / 未知 × 已存偏好为 null 或显式值）。先例：`core/settings.test.ts` 的纯派生断言。
- **Seam B（既有纯层，先例 `settings.test.ts`）**：设置读写——旧数据没有 `locale` 字段时读到 `null`（跟随系统）、写入后读回一致、非法值归 `null`，且音量与音画偏移的读取不受影响。
- **Seam C（既有纯层，先例 `rating.test.ts` / `progress.test.ts`）**：把「断言中文字面量」改成传入「回显键名与参数」的假文案函数，断言键名与参数而非具体措辞——文案以后再改也不必动这些测试。
- **Seam D（既有纯几何，先例 `hudGeometry.test.ts`）**：把印面与重击标记的尺寸收敛抽成纯函数（输入测量宽度 / 半径，输出矩形与字号），断言：印宽随字宽单调增长、印高不变、重击标号宽度不超过半径 1.4 倍、印面不越出画布边界。
- **不测**：画布实际像素、DOM 模板、itch 页的显示效果——由走查清单覆盖。这与既有口径一致（视觉与听感靠真实试玩验收）。
- **走查清单（11 屏，逐条人工过）**：标题 / 曲库 / 设置 / 键位引导 / 暂停 / 战斗 HUD（气血·蓄能·连击·判定·偏差·进度轨）/ 余韵三档与终章印章 / 结算卡与回放按钮 / 致命错画面 / 曲库角标切换即时生效 / itch 描述与 10 张截图。

### Out of Scope（范围外）

第三语言、语言包按需加载、字体打包、开发者报错与日志的翻译、测试名的翻译、两套语言各自的排行或存档差异（纪录不分语言）；以及 ADR-0008 里既有的全部非目标（独立分数系统、账号、云存档、排行榜、任何后端、触屏适配、原曲保真档）。
