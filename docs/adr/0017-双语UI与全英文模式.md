# 双语 UI：英文模式全英文，文案走一张集中表

界面支持中英双语。**英文模式下全英文——一个汉字都不留**，标题字、朱砂印、倒计时数词一并英文化；游戏名沿用拼音 *XinQin*（封面与 itch 标题早就这么写了）。所有玩家可见文案（约 105 条，原本散在 8 个运行时文件里）收进 `src/i18n/` 的一张表：一个 `MsgKey` 联合类型加中英两份 `Record<MsgKey, string>`，漏一条 `tsc` 就报错；带插值的句子（偏移建议、进度句、掌握度释义、判定偏差小字）是文案函数而不是模板字符串。默认语言跟随浏览器（`navigator.language` 以 `zh` 开头判中文，其余英文），玩家手选后写进 `settings.locale` 并记住——设置键仍是 `xinqin.settings.v1`，**不升版本号**，升版会连玩家已有的音量与音画偏移一起清零。itch 商店页、README、门面截图同步双语：中文内容一律保留，英文为新增。

为什么全英文而不是把印章、标题留作汉字：印章是印着两个汉字的**文字图形**，对外语玩家是乱码而不是落款；而倒计时那种 96px、一眼即读的位置上，中英混排会让人先解码再行动。整套视觉的水墨感靠字体、朱砂色与构图撑，不靠字形。为什么集中单表：一半文案在 `main.ts` 与 `renderer.ts` 两个大文件里，分散表会让「改一句话翻三个文件」，而缺键只能靠运行时兜底——编译期穷举把「漏翻」变成构建失败。为什么跟随浏览器：itch 来的英文玩家第一眼全是中文会直接关掉，而中文系统上（含开发者本机）默认仍是中文，现有体验不变。

## 后果

- **印面几何变了**。终章的朱砂印从「按两个汉字定死 232×123」改成按 `measureText` 自适应宽度：印围住词，而不是词挤进印面。标题角印仍是 40×40 方块，里面放拉丁字母 `X`（*XinQin* 首字母，读作落款）。
- **曲名一句两长**。曲库曲名栏宽 180px、22px 衬线，只容 12–14 个拉丁字符：卡农 *Canon in D*、致爱丽丝 *Für Elise* 放得下，春江花月夜 *Moonlight on the Spring River* 放不下——曲库用短名 *Spring River*，结算卡与键位引导用全名。这条「同一概念两个长度、都进词表」的规则对状态读数同样适用（HUD 用 *Heart 12/30*、*Phrase 3 / 7*）。
- **纯层函数签名要改**。`rating.offsetAdvice`、`progress.progressLine`、`mastery.masteryLine` 现在返回固定中文，改为接收文案函数；`rating.test.ts` / `progress.test.ts` 里断言中文字面量的用例随之改写——这是本次唯一动到既有测试的地方。
- **验收是两层**。一条单元测试扫两份字典：英文值里出现任何 CJK 字符即失败，中文值里出现整句英文即失败（`XinQin`、`S`–`C`、`×` 白名单放行）；再加一张 11 屏人工走查清单（标题 / 曲库 / 设置 / 键位引导 / 暂停 / 战斗 HUD / 余韵与终章 / 结算卡 / 回放 / 致命错 / itch 描述）。**不做**浏览器端逐屏巡检：仓库是 vitest 的 node 环境，脚手架成本比它挡住的错误多。
- **不上第二张语言表以外的东西**：不引入 i18n 库、不按需加载语言包、不打包字体。两份字典几 KB，一起进 bundle；英文模式的拉丁衬线靠系统字体栈（*Iowan Old Style* / Palatino / Georgia）前置，零体积。
