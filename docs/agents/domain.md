# Domain Docs

工程 skill 在探索代码库前应如何消费本仓库的领域文档。

## 探索前必读

- 仓库根目录的 **`GLOSSARY.md`**（本项目已有：心琴的领域词汇，如 斗琴 / 谱面 / 余韵 / 墨妖）
- **`docs/adr/`**：读与你要动的区域相关的 ADR（本项目现有 0001–0009）

若这些文件不存在，**静默继续**。不要提示缺失、不要建议预先创建。`/domain-modeling` skill（经 `/grill-with-docs`、`/improve-codebase-architecture` 触达）会在词条或决策真正落定时惰性创建它们。

## 文件结构

单上下文仓库（本项目即此）：

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-判定型节奏玩法.md
│   └── ...
└── (src/ 于实现期建立)
```

多上下文仓库以根目录存在 `GLOSSARY-MAP.md` 为标志；本项目不是。

## 使用词汇表的语言

当你的产出命名领域概念时（工单标题、重构提案、假设、测试名），使用 `GLOSSARY.md` 定义的术语，不要漂移到词汇表明确标记 _Avoid_ 的同义词。

若所需概念不在词汇表中，这是一个信号：要么你在发明项目不用的语言（请重新考虑），要么存在真实缺口（记下来交给 `/domain-modeling`）。

## 标记 ADR 冲突

若你的产出与现有 ADR 矛盾，显式指出而不是静默覆盖：

> _与 ADR-0007（余韵机制）矛盾，但值得重开，因为……_
