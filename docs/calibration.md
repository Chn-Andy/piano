## 一、判定窗口（定义口径）

**判定量只有一个**：|按键时刻 − 音符时刻|。音符时刻 = 音符**中心与判定线重合**的那一刻
（渲染层 `y = 判定线 − 剩余时间 × 340px/s`，所以这正是「滑块在线的中间附近」的可执行版）。
按键时刻取按下那一瞬的音频主时钟（ADR-0010）。与早/晚方向无关、与连击/密度/异色无关。

| 偏差（含等号） | 判定 | 伤害系数 | 连击 | 屏幕厚度（×340px/s） |
|---|---|---|---|---|
| ≤ 50ms | 完美 Perfect | ×1.0 | +1 | ±17px |
| ≤ 120ms | 良好 Good | ×0.7 | +1 | ±41px |
| > 120ms | 失误 Miss | 无（剑气扑空） | 归零 | — |

| 常量 | 当前值 | 调整入口 |
|---|---|---|
| Perfect 半宽 | ±50ms（边界含） | `src/core/config.ts` → `JUDGMENT_WINDOWS.perfect` |
| Good 半宽 | ±120ms（边界含） | `src/core/config.ts` → `JUDGMENT_WINDOWS.good` |

**三条口径**（测试钉着：`src/core/simulator.test.ts`「判定窗口边界」）：
1. **边界含等号**：恰好 50ms 判完美、恰好 120ms 判良好。
2. **一颗音符只判一次**：命中即消费；**早于良好窗的按键不消耗音符**（音符继续等，那次按键
   只是空按，只有琴声没有判定），迟过良好窗才落失误。
3. **失误由时间判出**：音符等到「时刻 + 120ms」才 Miss，不是按键判出来的。

**理由**：50ms 约一至两个显示帧（60Hz 一帧 16.7ms），吸收人因抖动后仍能区分"很准"与"准"；
Good 120ms ≈ 2.4 × Perfect，中间档不苛责。判定一律以音频主时钟为准（ADR-0010），程序化实测
证明管线零系统误差（`?auto=perfect` 全 Perfect、平均偏差 0ms，见文末）；**本票未调窗口**——
窗口的最终手感属真实设备人工验收范畴（工单第 4 条，待用户试玩），无试玩证据不动。

**偏差可见性（ADR-0013）**：完美带在屏幕上只有 34px 高、比一颗音符（26px）还窄，肉眼根本
分辨不出「这次差 30ms 还是 90ms」。所以偏差必须写成数字——判定闪示的「早 12 / 晚 43」小字、
结算的「精度 %」与「按键平均偏早/偏晚 N ms（≥8ms 直接给偏移建议）」、判定线上按窗口折算的
两道墨晕（纯视觉，只是让「线的中间附近」看得见）。改窗口数值时这三处自动跟着变，不必改渲染
结构。

## 二、音画偏移（SPEC 故事 22）

| 常量 | 当前值 | 调整入口 |
|---|---|---|
| 默认偏移 | 0 ms | `src/core/settings.ts` → `DEFAULT_SETTINGS.offsetMs` |
| 滑条范围 / 步进 | ±150 ms / 5 ms | `src/core/settings.ts` → `OFFSET_LIMIT_MS`；面板步进在 `src/main.ts` `showSettings()` |
| 默认音量（两轨） | 各 1.0（直通） | `src/core/settings.ts` → `DEFAULT_SETTINGS` |

**语义**（UI 文案同款）：正值 = 你的按键被判定得整体更「早」；负值更「晚」。实现为按键时刻**进模拟器前**的时间平移（`judgedTime()`，`press()` 内唯一生效点），全项目只有这一处偏移（ADR-0010：不出现第三套钟）。琴声不受偏移影响——钢琴按哪刻响哪刻，校准的是判定，不是弹奏。真人按键与 `?auto` 自动弹奏共用同一条管线，故下表的程序化实测即为真实生效路径。

**范围理由**：±150ms 覆盖一至两个显示帧的常见滞后；再大说明设备/谱面有别的问题，不是校准能救的。

**程序化实测**（`?auto=perfect&song=fur-elise&chart=easy`，79 音符，2026-10-24，内置浏览器）：

| 偏移 | 结果 | 结论 |
|---|---|---|
| 0 ms | 完美 79 / 良好 0 / 失误 0 → 胜利 · S · 新纪录 | 管线零系统误差 |
| +60 ms | 完美 0 / 良好 26+（读数点）/ 失误 0 | 每个准点按键被判早 60ms → 全 Good：偏移确在判定上生效 |
| +130 ms | 失误 17 → 血空败局（v1 时代：17 × 反击 6 = 102 ≥ 100） | 偏移超出 Good 窗后连准点也救不回。**v1.1 起反击扣血已删（ADR-0011）**：同一偏移下 miss 不再掉血，败因改为墨潮推平——此行是 v1 的历史记录 |

### v1.1 的关键裁定

1. **归因重构（ADR-0011）**：Miss 不再扣血（`COUNTER_DAMAGE` 已删除）——玩家血量唯一的
   来源是怪物推进到琴阵后的咬线；扑空只留视觉（判定线斜笔）与风声。
2. **墨妖厚度必须卡在两个玩家模型之间**：认真玩家每音符期望 8 点，普通玩家约 4.5–5 点
   （≈ 0.6 个认真）。低于 0.6 时普通玩家也能清完一波；高于 0.8 时认真玩家的余量被吃掉。
   **0.7 是九谱面全量搜索里唯一同时满足四条约束的一档**（14 号票把**简单**档下调到 0.55，
   中等/高级仍 0.7，理由与实测见下节「v1.2 容错定标」）。08 号票曾定 0.4——那是在
   稀疏的卡农谱面上定的标，漏了带和弦的致爱丽丝 / 春江：和弦重击让普通玩家的实际输出
   高一截，0.4 与 0.55 下普通玩家 9 局 7 胜。这是本票最重要的发现。
3. **难度加在血量端，不加在催促端**：推进耗时保持 19 秒、咬线伤害保持 10——守线压力
   仍是「下一只何时到线」，而不是「跑得更快 / 咬得更疼」。
4. **琴心与血量联动**：琴心给每个玩家的总输出加了约「命中数 / 30 × 6」颗音符的火力，
   血量端已把这份火力补回去（否则普通玩家被琴心白送成胜局）。一炮 ≈ 6 颗完美命的全场
   火力，不足以独力斩首墨主（那是终章的事）。

### v1.2 容错定标（14 号票：简单难度的失误代价）

**用户试玩反馈**：很简单的关卡里「要按的琴键很少、怪却挺多」，一颗失误就掉血。

**诊断**（程序化实测，不是感觉）：掉血量 ≈ 漏过来的残血 ÷ 玩家每秒输出，而
咬线速率是固定的 10 点/秒（每 1 秒一口、每口 10 血）。简单谱面稀疏——卡农简单
0.47 音/秒、秒伤 5–9 点，春江简单 0.58 音/秒——一只带残血抵阵的墨妖要啃好几口
才补得掉；高级谱面秒伤 20–40 点，残血一两颗音符就清了。也就是说**同一颗失误，
在简单难度上的血量代价被秒伤差放大了 3–5 倍**。另有一处独立的结构问题：墨主
原按「末波波首」登场，而末波可能短于一个行程（春江简单末波只有 7 秒），墨主
于是只在末尾 4 颗音符里承伤——斩不下就歌毕留怪判负，一颗失误直接翻盘。

**两处改动**：

1. `HORDE_PLAN.DEMON_HP_FRACTION` 改为**按难度分档**：简单 0.7 → **0.55**，中等/高级维持 0.7。
2. `planMonsters` 的墨主**抵阵不晚于终章乐句开始**（`spawnAt = min(末波波首, 终章起 − 行程)`；
   无乐句谱面维持末波波首），使它能在整个终章里挨打。

**实测（每 n 颗失手一颗，程序化整局）**：

| 谱面 | 容错阈值（改前 → 改后） | 20% 失手的终局（改前 → 改后） |
|---|---|---|
| 卡农 简单 | 17% → **25%** | 血空 10 口 → **满血 0 口清场** |
| 致爱丽丝 简单 | 17% → **25%** | 血空 10 口 → **满血 0 口清场** |
| 春江花月夜 简单 | 13% → **25%** | 满血但墨主残留 25/40 → **满血 0 口清场** |
| 卡农 中等 | 8% → **17%** | （原被墨主锁死：墨主 16/60 残留） |
| 致爱丽丝 中等 | 20% → **25%** | — |
| 卡农 高级 | 10% → 10% | — |
| 春江花月夜 中等 / 高级 | 20% / 25% → 不变 | — |

四条红线（完美/认真九谱面全胜、普通九谱面全败、静置必被咬空）**全部保持**；
普通玩家（三失其一）仍在九张谱面上全败——简单难度变宽容，但没有变成送分。

### 敏感性（改动这些常量前先看一眼）

哪些旋钮一动就会破红线？在九谱面矩阵上逐项扫（2026-10-27）：

| 调整 | 结果 | 结论 |
|---|---|---|
| 寒音 减速 ×1.5 + 击退双倍 | 四条红线仍成立 | 寒音是纯控场，强度宽松 |
| 寒音 减速 ×0.5 + 击退半倍 | 仍成立 | 同上 |
| 毒音 每拍伤害 ±50% | 仍成立 | 毒音只磨最前一只，影响面窄 |
| 爆音 25% → 40%（+60%） | **普通玩家在致爱丽丝 hard 翻盘**（清空全场、满血） | **爆音是最敏感的旋钮**：它同时打前二只且按身板结算，和弦密的谱面上等于多一轮火力 |
| 爆音 25% → 10%（−60%） | 仍成立 | 上限比下限更危险 |

异色**频率**（6%）不进运行时：它是构建期写进谱面的常量，改动须重跑 `npm run charts`，九张产物的音符级比例实测 5.3%–6.3%（票面 5–8%），矩阵本身就是在这些产物上跑的。

**实测印证**（词条化，均为程序化三玩家模型）：

| 玩家模型 | 九谱面结果 | 终局血量 |
|---|---|---|
| 完美 | 9/9 胜 | 100（满分不挨咬） |
| 认真（95% 命中） | 9/9 胜 | 最差 80（卡农 hard） |
| 普通（三失其一） | 9/9 败 | 多数血空；致爱丽丝 hard / 春江 hard 以怪残留告负 |
| 静置 | 9/9 败 | 血空（咬线 10 口） |

**总设计目标不变**：普通玩家整首打不完、认真弹能清完（SPEC）。

## 五、音频分轨与响度

**拓扑**：`destination ← master(0.9) ← ┬ musicBus（玩家音量，默认 1）← 琴声采样`；`└ sfxBus（玩家音量，默认 1）← 全部战斗音效`。两轨独立增益（SPEC 故事 23），默认 1/1 直通——**出厂混音 = 各音效合成时定标的相对响度**，与工单 05 时代听感完全一致。master 0.9 在 `src/audio/engine.ts` `start()`。

**响度设计原则**（粗定标）：频次越高越轻（命中声最频繁 → 最克制）；瞬态越短可越响；一切音效在琴声之下或缝隙里——琴声是主角，音效是手感层。分层不互盖靠三点：独立增益轨、频段错开（命中声走 ≥1.8kHz 高通，低频留给重击/反击/印章）、时值克制（命中 90ms）。

| 音效 | 合成 | 峰值增益 | 频次定位 | 入口（`engine.ts`） |

| 命中剑气·普通 | 高通白噪 90ms + 三角波 1.9→1.4kHz | 0.07 + 0.045 | 最高频 | `hitStrike(when, false)` |

## 七、演奏幻想（v1.4：进度轨 / 伴奏 / 掌握度 / 回放）

票 17–19 只增加可见性与听觉，**一个对局数值都没动**（血量、咬线、充能、判定窗口、伤害、
谱面）。下表是这一批新增的可调项；「理由」写的是取舍，不是可推导的定标。

| 常量 | 当前值 | 入口 |
|---|---|---|
| 伴奏和声窗口 | 2 拍（60bpm 两秒、72bpm 1.67 秒） | `src/converter/accompaniment.ts` → `ACCOMPANIMENT_WINDOW_BEATS` |
| 谱面伴奏声部数（按难度） | 简单 1 / 中等 3 / 高级 4 | `src/core/config.ts` → `ACCOMPANIMENT_PLAN[*].chartVoices` |
| 合成铺底声部数（按难度） | 简单 1 / 中等 2 / 高级 3 | `ACCOMPANIMENT_PLAN[*].padVoices` |
| 伴奏每音力度（按难度） | 0.50 / 0.55 / 0.60（玩家琴声恒 1.0） | `ACCOMPANIMENT_PLAN[*].gain` |
| 精熟门槛 | 零失误且精度 ≥ 0.90（边界含） | `MASTERY.MASTERED_ACCURACY` |
| 回放窗口 | 本局最后 20 秒（不足则从头） | `src/core/replay.ts` → `REPLAY_SECONDS` |
| 回放起点余量 | 0.12 秒（第一颗音落在音频时间线未来） | `src/core/replay.ts` → `REPLAY_LEAD` |

**理由摘要**：

- **声部数**：ADR-0016「伴奏的密度与力度按难度给」。简单只留低音（稀疏谱面要听清自己的旋律），
  中等三和弦分解，高级补一条内声部。不随表现动态加厚——那会把伴奏变成隐藏评分。
- **力度**：每音增益乘在钢琴采样上（采样只有一层力度 v8，力度只能靠增益做）。简单最轻
  （0.50）让旋律最突出；高级最厚（0.60）托住密集的旋律，但相对玩家琴声仍是 −4.4 dB——
  旋律永远是主角。伴奏与玩家琴声同在音乐轨（`musicBus`），两者一起受「琴声音量」控制。
  伴奏是分解织体（同刻只有一声），所以不按声部数反比压，否则高级的和弦会薄得听不出三度。
- **掌握度**：精熟只由「零失误且精度 ≥ 90%」判，边界含等号。纪录里的判据是一条单调最佳事实
  （零失误局的最高精度，只升不降），因此一次达标的局不会被后来评级更高、精度更低的一局抹掉；
  旧版纪录无此事实时降级为弹熟，不猜。
- **回放**：20 秒是票面口径（最后 20 秒 + 终章）；起点余量 0.12 秒与演奏时的 `PLAY_EPSILON`
  同理——把第一颗音放进音频时间线的未来，避免爆音。播完按音频时钟复位（按钮回「听我的演奏」），
  重复点击先停再放。

## 八、再定标流程（未来调参者照此办理）

1. **程序化三件套**（零成本回归）：`?auto=perfect` 偏移 0 / +60 / +130 各跑一局，期望结果见第二节表格；判定计数与平均偏差经 `window.__xq`（`perfect/good/miss/avgOffsetMs`）读取——零偏移应得 `avgOffsetMs = 0`，+60 偏移应得约 **−60**（正=迟；正向偏移把判定整体前移，抵消「按键总是偏晚」）。这一对数同时钉住偏移语义与判定口径。
2. **边界单测**：`npx vitest run src/core/settings.test.ts`——偏移翻转判定档的边界（±窗口、方向语义）有钉子，改窗口或偏移语义会立刻红。
3. **真实设备人工验收**（本票第 4 条，**待用户试玩**）：整首游玩，重点感受——判定手感是否公平（不准先调偏移再议窗口）、闪示的「早/晚 N」是否与自己手感一致（若整局都在「晚」，先调偏移而不是怪窗口）、命中剑气声是否吵、两轨音量配比、和弦重击的分量、终章印章落点。有人工证据再动数值，并把调整理由记进对应表行。
4. **定标性质回归**（改任何战斗常量后必跑）：`npx vitest run src/core/combat.test.ts`——三曲 × 三难度 × 三玩家模型 36 项性质（完美/认真全胜、普通全败、静置被咬空）。这是数值改动的红线，红了就说明某个玩家模型被破坏。
5. **浏览器整局链路**：`?auto=perfect`（应当胜、结算显示琴心次数）与 `?auto=idle`（应当败于咬空）各跑一局，读数经 `window.__xq` 读取（`perfect/good/miss/avgOffsetMs/playerHp/monstersAlive/bites/tintCold/tintToxic/tintBlast/poisonTicks/qinxinGauge/qinxinReleases`）。
6. 全量测试 + `npm run build` 必须绿；**v1.4 基线为 349 项测试**（v1 153 → 08 号票 172 → 09 号票 189 → 12 号票 222 → 14 号票 224 → 15 号票 231 → 16 号票 232 → 票 17 后 282 → 票 19 后 326 → v1.4 两轴审查修复后 349；票 18 在自己的分支上是 254，合并后以主线为准）。
