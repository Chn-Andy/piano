## 一、判定窗口

| 常量 | 当前值 | 调整入口 |
|---|---|---|
| Perfect 半宽 | ±50ms（边界含） | `src/core/config.ts` → `JUDGMENT_WINDOWS.perfect` |
| Good 半宽 | ±120ms（边界含） | `src/core/config.ts` → `JUDGMENT_WINDOWS.good` |

**理由**：50ms 约一至两个显示帧（60Hz 一帧 16.7ms），吸收人因抖动后仍能区分"很准"与"准"；Good 120ms ≈ 2.4 × Perfect，中间档不苛责。判定一律以音频主时钟为准（ADR-0010），程序化实测证明管线零系统误差（`?auto=perfect` 全 Perfect，见文末）；**本票未调**——窗口的最终手感属真实设备人工验收范畴（工单第 4 条，待用户试玩），无试玩证据不动。

**边界口径**：|按键 − 音符| ≤ 半宽即判入（含等号）；超出 Good 窗不判定，音符等 Miss。边界行为有回归测试钉着（`src/core/simulator.test.ts`「判定窗口边界」、`src/core/settings.test.ts`「零偏移 = 现状回归保护」）。

## 二、音画偏移（SPEC 故事 22）

| 常量 | 当前值 | 调整入口 |
|---|---|---|
| 默认偏移 | 0 ms | `src/core/settings.ts` → `DEFAULT_SETTINGS.offsetMs` |
| 滑条范围 / 步进 | ±150 ms / 5 ms | `src/core/settings.ts` → `OFFSET_LIMIT_MS`；面板步进在 `src/main.ts` `showSettings()` |
| 默认音量（两轨） | 各 1.0（直通） | `src/core/settings.ts` → `DEFAULT_SETTINGS` |

**语义**（UI 文案同款）：正值 = 你的按键被判定得整体更「早」；负值更「晚」。实现为按键时刻**进模拟器前**的时间平移（`judgedTime()`，`press()` 内唯一生效点），全项目只有这一处偏移（ADR-0010：不出现第三套钟）。琴声不受偏移影响——钢琴按哪刻响哪刻，校准的是判定，不是弹奏。真人按键与 `?auto` 自动弹奏共用同一条管线，故下表的程序化实测即为真实生效路径。

**范围理由**：±150ms 覆盖一至两个显示帧的常见滞后；再大说明设备/谱面有别的问题，不是校准能救的。

**程序化实测**（`?auto=perfect&song=fur-elise&chart=easy`，79 音符，2026-10-24，内置浏览器）：

| 偏移 | 结果 | 结论 |
|---|---|---|
| 0 ms | 完美 79 / 良好 0 / 失误 0 → 胜利 · S · 新纪录 | 管线零系统误差 |
| +60 ms | 完美 0 / 良好 26+（读数点）/ 失误 0 | 每个准点按键被判早 60ms → 全 Good：偏移确在判定上生效 |
| +130 ms | 失误 17 → 血空败局（v1 时代：17 × 反击 6 = 102 ≥ 100） | 偏移超出 Good 窗后连准点也救不回。**v1.1 起反击扣血已删（ADR-0011）**：同一偏移下 miss 不再掉血，败因改为墨潮推平——此行是 v1 的历史记录 |

### v1.1 的关键裁定

1. **归因重构（ADR-0011）**：Miss 不再扣血（`COUNTER_DAMAGE` 已删除）——玩家血量唯一的
   来源是怪物推进到琴阵后的咬线；扑空只留视觉（判定线斜笔）与风声。
2. **墨妖厚度必须卡在两个玩家模型之间**：认真玩家每音符期望 8 点，普通玩家约 4.5–5 点
   （≈ 0.6 个认真）。低于 0.6 时普通玩家也能清完一波；高于 0.8 时认真玩家的余量被吃掉。
   **0.7 是九谱面全量搜索里唯一同时满足四条约束的一档**。08 号票曾定 0.4——那是在
   稀疏的卡农谱面上定的标，漏了带和弦的致爱丽丝 / 春江：和弦重击让普通玩家的实际输出
   高一截，0.4 与 0.55 下普通玩家 9 局 7 胜。这是本票最重要的发现。
3. **难度加在血量端，不加在催促端**：推进耗时保持 19 秒、咬线伤害保持 10——守线压力
   仍是「下一只何时到线」，而不是「跑得更快 / 咬得更疼」。
4. **琴心与血量联动**：琴心给每个玩家的总输出加了约「命中数 / 30 × 6」颗音符的火力，
   血量端已把这份火力补回去（否则普通玩家被琴心白送成胜局）。一炮 ≈ 6 颗完美命的全场
   火力，不足以独力斩首墨主（那是终章的事）。

### 敏感性（改动这些常量前先看一眼）

哪些旋钮一动就会破红线？在九谱面矩阵上逐项扫（2026-10-27）：

| 调整 | 结果 | 结论 |
|---|---|---|
| 寒音 减速 ×1.5 + 击退双倍 | 四条红线仍成立 | 寒音是纯控场，强度宽松 |
| 寒音 减速 ×0.5 + 击退半倍 | 仍成立 | 同上 |
| 毒音 每拍伤害 ±50% | 仍成立 | 毒音只磨最前一只，影响面窄 |
| 爆音 25% → 40%（+60%） | **普通玩家在致爱丽丝 hard 翻盘**（清空全场、满血） | **爆音是最敏感的旋钮**：它同时打前二只且按身板结算，和弦密的谱面上等于多一轮火力 |
| 爆音 25% → 10%（−60%） | 仍成立 | 上限比下限更危险 |

异色**频率**（6%）不进运行时：它是构建期写进谱面的常量，改动须重跑 `npm run charts`，九张产物的音符级比例实测 5.3%–6.3%（票面 5–8%），矩阵本身就是在这些产物上跑的。

**实测印证**（词条化，均为程序化三玩家模型）：

| 玩家模型 | 九谱面结果 | 终局血量 |
|---|---|---|
| 完美 | 9/9 胜 | 100（满分不挨咬） |
| 认真（95% 命中） | 9/9 胜 | 最差 80（卡农 hard） |
| 普通（三失其一） | 9/9 败 | 多数血空；致爱丽丝 hard / 春江 hard 以怪残留告负 |
| 静置 | 9/9 败 | 血空（咬线 10 口） |

**总设计目标不变**：普通玩家整首打不完、认真弹能清完（SPEC）。

## 五、音频分轨与响度

**拓扑**：`destination ← master(0.9) ← ┬ musicBus（玩家音量，默认 1）← 琴声采样`；`└ sfxBus（玩家音量，默认 1）← 全部战斗音效`。两轨独立增益（SPEC 故事 23），默认 1/1 直通——**出厂混音 = 各音效合成时定标的相对响度**，与工单 05 时代听感完全一致。master 0.9 在 `src/audio/engine.ts` `start()`。

**响度设计原则**（粗定标）：频次越高越轻（命中声最频繁 → 最克制）；瞬态越短可越响；一切音效在琴声之下或缝隙里——琴声是主角，音效是手感层。分层不互盖靠三点：独立增益轨、频段错开（命中声走 ≥1.8kHz 高通，低频留给重击/反击/印章）、时值克制（命中 90ms）。

| 音效 | 合成 | 峰值增益 | 频次定位 | 入口（`engine.ts`） |
|---|---|---|---|---|
| 命中剑气·普通 | 高通白噪 90ms + 三角波 1.9→1.4kHz | 0.07 + 0.045 | 最高频 | `hitStrike(when, false)` |

## 七、再定标流程（未来调参者照此办理）

1. **程序化三件套**（零成本回归）：`?auto=perfect` 偏移 0 / +60 / +130 各跑一局，期望结果见第二节表格；判定计数经 `window.__xq`（`perfect/good/miss`）读取。
2. **边界单测**：`npx vitest run src/core/settings.test.ts`——偏移翻转判定档的边界（±窗口、方向语义）有钉子，改窗口或偏移语义会立刻红。
3. **真实设备人工验收**（本票第 4 条，**待用户试玩**）：整首游玩，重点感受——判定手感是否公平（不准先调偏移再议窗口）、命中剑气声是否吵、两轨音量配比、和弦重击的分量、终章印章落点。有人工证据再动数值，并把调整理由记进对应表行。
4. **定标性质回归**（改任何战斗常量后必跑）：`npx vitest run src/core/combat.test.ts`——三曲 × 三难度 × 三玩家模型 36 项性质（完美/认真全胜、普通全败、静置被咬空）。这是数值改动的红线，红了就说明某个玩家模型被破坏。
